## Goal

Add an optional `timezone` parameter to `formatDate` in `src/utils.ts`. Default behavior must stay identical to today.

## Acceptance Criteria

- [ ] `formatDate(date, timezone?: string)` — second argument is optional, defaults to `"UTC"`.
- [ ] When timezone is omitted or `"UTC"`, output is byte-identical to the current implementation.
- [ ] When a valid IANA tz string is passed (e.g. `"Asia/Tokyo"`, `"America/New_York"`), the date is formatted in that zone.
- [ ] Add 3 tests in `tests/utils.test.ts`: one with `"UTC"`, one with `"Asia/Tokyo"`, one with no second argument.
- [ ] `npm test` passes (all old tests + new ones).

## Constraints

- Do not modify other functions in `src/utils.ts`.
- Keep TypeScript `strict` mode happy.

## Out of Scope

- Locale / month-name changes.
- Time-of-day formatting.

## Hints

- `Intl.DateTimeFormat(timezone, { ... }).formatToParts(date)` is the standard way.
